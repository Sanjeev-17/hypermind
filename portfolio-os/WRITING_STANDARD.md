# Writing Standard

**Status:** Permanent Portfolio OS standard  
**Applies to:** Every skill that generates or revises text  
**Owner:** editorial-director (steward) · all text-producing skills (compliance)

This is the **writing constitution** — not a visual style guide and not homepage copy.

---

## Philosophy

Writing should feel:

- experienced  
- thoughtful  
- concise  
- confident  
- human  
- technically accurate  
- conversational when appropriate  
- product-minded  

It must **never** feel like AI-generated marketing copy.

---

## Anti-AI writing rules

### Banned words / phrases

Do not use:

- seamless  
- leverage  
- utilize  
- robust  
- transformative  
- revolutionary  
- cutting-edge  
- empower  
- unlock potential  
- synergy  
- best-in-class  
- world-class (unless factually justified with evidence)  
- innovative (without evidence)  
- intuitive (without explaining why)  
- user-centric (without demonstrating it)  
- delve  
- landscape  
- holistic  
- comprehensive solution  
- drive impact  
- drive innovation  

### Buzzword rule

Ban generic UX/product buzzwords unless supported by **evidence** in the same passage.

---

## Sentence structure

**Prefer:** short sentences · natural rhythm · concrete language · specific nouns · active voice · real examples  

**Avoid:** long introductions · corporate filler · over-explaining · repeating ideas · AI disclaimers · empty transitions  

---

## Product design writing

Every substantive statement should make clear, where relevant:

| Question | Required? |
|----------|-----------|
| What changed? | Yes for work claims |
| Why? | Yes for decisions |
| How? | When process matters |
| Evidence? | Yes for impact/leadership/ownership |
| Tradeoffs? | Yes for decisions |
| Outcome? | Yes if claiming results |

Never describe work without the **decision** behind it.

---

## Tone

Professional. Calm. Curious. Confident.

Never arrogant. Never salesy. Never exaggerated.

---

## Evidence rule

Do **not** invent: metrics · ownership · business impact · leadership · results  

If evidence is missing: mark clearly (`Needs validation` / `Do not publish yet` / omit).

---

## KISS rule

If two sentences say the same thing, keep the shorter one.

---

## Editing checklist

Before accepting any text:

- [ ] Remove fluff  
- [ ] Remove repeated ideas  
- [ ] Replace abstractions with specifics  
- [ ] Shorten where possible  
- [ ] Verify claims  
- [ ] Improve readability  
- [ ] Remove AI-sounding phrases  
- [ ] Remove unnecessary adjectives  

---

## Reading test

Could an experienced design director believe a **human** wrote this?

If not → rewrite.
