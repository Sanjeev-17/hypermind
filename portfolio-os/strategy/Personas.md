# Personas — Portfolio audience model

**Status:** Authoritative  
**Owner:** portfolio-architect  
**Product goal:** Maximize interview conversions for a Senior Product Designer (6+ years).  
**Core message:** I solve complex product problems and communicate my thinking clearly.  
**Not the goal:** Impress peer designers. Visual applause is secondary to hire confidence.

Source canvas: Cursor canvases `portfolio-hiring-personas.canvas.tsx` (interactive explorer).

---

## Assumption to kill

Most portfolios are designed for peer designers. The first two gates are sourcers and recruiters with under a minute. If they cannot parse seniority and fit, the hiring manager never opens a case study.

Optimize for decision speed first, depth second — via progressive disclosure, not dilution.

## Critical personas (design against these first)

### Priya — Design Recruiter
- **Needs:** Seniority + domain fit in ~15s; copyable outcome lines; one best-case link
- **Bounce:** Philosophy homepage, buried work, unclear ownership, no resume
- **Homepage:** Identity + domain + proof chips. No manifesto.
- **Case:** Problem + outcome + ownership above the fold
- **Motion:** Never delay scannable facts

### Marcus — Sourcer
- **Needs:** Fast load, mobile-readable, product case titles, resume PDF
- **Bounce:** Password walls, Dribbble-only, heavy intros, “let’s chat” only
- **Homepage:** Work grid + always-visible resume
- **Motion:** No intro gates; first paint first

### Elena — Hiring Manager
- **Needs:** Judgment under ambiguity; tradeoffs; real impact; PM/eng partnership
- **Bounce:** Process theater, fake metrics, UI galleries, walls of text
- **Homepage:** Problem-solver positioning + decision/outcome teasers
- **Case:** Context → stakes → options → choice → result → reflection
- **Motion:** Sequence argument; never impress

### Jordan — Staff/Principal peer
- **Needs:** Proven authorship; systems/flows/states; defendable craft
- **Bounce:** Stolen credit, hero shots only, shallow research, over-designed site chrome
- **Case:** Ownership labels (led / co-led / contributed); artifact-rich middle; “what I’d change”
- **Motion:** Subtle — decorative motion signals insecurity

## High-influence notes (by company type)

| Audience | Overweight | Underweight |
|----------|------------|-------------|
| Figma / Adobe / Linear | Taste, interaction detail, agency | Enterprise process decks |
| Stripe / Airbnb / Rippling / Atlassian | Product judgment, constraints, impact | Moodboards |
| Mastercard / Razorpay / CRED / PhonePe | Scale, trust/risk, metrics literacy | Pure delight narratives |
| Founders (Series A–C) | High-agency 0→1, speed, taste | Double-diamond ceremony |
| Google-style committees | Consistent evidenced claims | Hype language |

One portfolio. Case selection and framing serve each audience — do not fragment into microsites.

## Design principles (from personas only)

1. Impact before process  
2. Decisions over deliverables  
3. 15-second homepage parse  
4. Ownership made explicit  
5. Progressive disclosure of complexity  
6. Evidence over assertion  
7. Product language, not designer dialect  
8. Constraints are credibility  
9. Two or three deep cases beat seven shallow ones  
10. One shareable best-work link  
11. Motion serves hierarchy  
12. Every interaction reduces cognitive load  
13. Interview-defendable narratives only  
14. Show ambiguity handling  
15. Systems and leverage signal seniority  
16. Taste without theater  
17. Fintech realism where relevant  
18. Founder path ≠ enterprise path  
19. Operational reliability is part of design  
20. Reflection beats perfection

## IA implication

Homepage (15s identity + proof) → Work index (scannable outcomes) → 2–3 deep cases (decision-first) → About (operating stance) → Resume PDF always available. Optional systems/platform case for director/staff altitude.

---

## Anti-audience

Do not optimize for: designer Twitter applause, award-site aesthetics, exhaustive process documentation, motion reels. Those convert admiration, not calendar invites.
